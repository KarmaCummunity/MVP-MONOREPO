## 🚨 Critical Vulnerabilities

* **[CRITICAL] Tracked production/development credentials and user backup data remain in Git.** `apps/api/railway_vars.txt:8-37` contains a credentialed database URL, Google API key, and JWT secret; `apps/api/railway.toml.dev:34` contains another JWT secret; `apps/api/src/main.ts:149-190` embeds recognizable database-password fragments; `apps/api/data-backups/20251224-162421/users.json` contains user and password-hash material. - File: `apps/api/railway_vars.txt`, `apps/api/railway.toml.dev`, `apps/api/src/main.ts`, `apps/api/data-backups/20251224-162421/users.json` -> Action: Rotate/revoke every exposed credential and active token session, purge secrets and backups from Git history, replace password-fragment environment detection with non-secret deployment identifiers, and enable CI secret scanning.
* **[CRITICAL] Two public legacy auth routes permit account takeover.** `POST /api/users/login` declares `password` optional and verifies it only when both a password and hash are present (`user-auth.service.ts:35-38`, `190-263`), so an email-only request returns a successful user session response. `POST /api/users/resolve-id` has no guard (`users.controller.ts:183-188`), accepts unverified identifiers, can link caller-supplied IDs (`user-auth.service.ts:270-342`, `580-630`), and mints access/refresh tokens (`user-auth.service.ts:645-672`). - File: `apps/api/src/controllers/users.controller.ts`, `apps/api/src/services/user-auth.service.ts` -> Action: Require password verification on legacy login; require a verified Firebase/Google credential or authenticated session before resolution/linking; never mint tokens from identifier knowledge alone; rate-limit and audit both routes.
* **[CRITICAL] Profile and hierarchy APIs authorize spoofable client identities instead of the JWT actor.** Any JWT holder can update another profile and write `roles`, `firebase_uid`, or `password_hash` through `PUT /api/users/:id` (`users.controller.ts:126-132`, `user-profile.service.ts:254-361`). Promotion routes trust body `requestingAdminId`, `set-manager` skips authorization when `requestingUserId` is omitted, and hierarchy management never proves the caller owns `managerId` (`users.controller.ts:45-88`, `user-hierarchy.service.ts:492-517`, `600-703`, `871-1050`). - File: `apps/api/src/controllers/users.controller.ts`, `apps/api/src/services/user-profile.service.ts`, `apps/api/src/services/user-hierarchy.service.ts` -> Action: Derive actors only from `req.user`, enforce self-or-admin ownership and `AdminAuthGuard`, remove privileged fields/actor IDs from public DTOs, and add negative permission-matrix tests.
* **[CRITICAL] Multiple production controllers expose PII or mutations without effective authentication/ownership.** Confirmed surfaces include optional-auth chat reads and sender impersonation (`chat.controller.ts:45-46`, `246-269`, `341-465`), all ride create/book/approve/update/delete routes (`rides.controller.ts:37-47`, `374-577`, `695-761`), item lifecycle controllers (`items-delivery.controller.ts:25+`, `dedicated-items.controller.ts:19-171`), CRM/community-member CRUD, and session enumeration/logout-all (`session.controller.ts:136-228`). `RateLimitController` is always registered and lets unauthenticated callers clear or stress arbitrary identifiers (`rate-limit.controller.ts:20-176`, `app.module.ts:90-122`). - File: `apps/api/src/controllers/`, `apps/api/src/items/dedicated-items.controller.ts`, `apps/api/src/auth/controllers/session.controller.ts` -> Action: Establish a route access-control matrix, require JWT/admin guards, derive identity from the token, enforce resource membership/ownership, and exclude test controllers from production.
* **[CRITICAL] Known exploitable dependency chains remain in the lockfile.** Final-HEAD verification reports **56 vulnerabilities: 2 critical, 40 high, 12 moderate, 2 low**. Critical transitive findings are `handlebars` JavaScript injection and `shell-quote` command injection. - File: `package-lock.json`, workspace `package.json` files -> Action: Upgrade direct parents/overrides, regenerate the lockfile, validate whether vulnerable toolchains process untrusted input, and add an audited dependency gate to CI.

## 🐞 Bugs & Logic Issues

* **Editing a post persists device-local image URIs and truncates multi-image posts.** The picker sends `file://`/`content://` directly (`EditPostModal.tsx:51-75`, `97-121`), while the API replaces `images` with a single-element array (`posts.controller.ts:2349-2356`). Other devices receive a broken URI and all secondary images are silently lost. - Recommendation: Upload local assets first and send a complete `images[]` contract; preserve unchanged images and cover remote/local/removal/multi-image cases.
* **Admin task pagination can omit root tasks and skip whole pages.** Default non-done statuses make the server treat every request as filtered and suppress `parent_task_id IS NULL` (`useAdminTasksScreen.tsx:329-376`, `tasks-list-query.service.ts:136-155`); the client filters subtasks only after pagination. Repeated `onEndReached` calls can also advance multiple pages while the sequence guard discards earlier responses (`useAdminTasksScreen.tsx:220-225`, `352-426`). - Recommendation: Make `root_only` independent of other filters, enforce it before pagination, add a load-more in-flight guard, and advance the cursor only after success.
* **Concurrent authenticated requests can hang permanently when token refresh fails.** Waiting 401 requests subscribe only to a success callback, while failure clears the subscriber array without resolving or rejecting promises (`auth/interceptors/authFetchInterceptor.ts:9-19`, `46-89`). - Recommendation: Store resolve/reject subscribers, reject every waiter on refresh failure, and add concurrent refresh success/failure tests.
* **Request traffic can trigger destructive schema mutation.** `ensurePostsTable()` runs from feed/comment paths and executes `DROP TABLE IF EXISTS posts CASCADE` when expected columns are absent (`posts.controller.ts:67-79`, `176-223`, `842-843`, `1597-1600`). A partial migration or renamed column can erase posts and dependent data during an ordinary request. - Recommendation: Remove all DDL from request paths, use versioned migrations, and fail closed with an operational alert on schema mismatch.
* **Ride and item approval flows permit double allocation.** Ride booking approval updates status before checking capacity and has no row lock (`rides.controller.ts:505-566`); item approval marks an item reserved without an availability compare-and-set or rejecting competing requests (`items-delivery.service.ts:466-558`). - Recommendation: Lock/atomically condition the resource row, validate capacity/availability before mutation, reject competing pending requests in the same transaction, and add concurrent-approval tests.

## 🏗️ Architecture & Clean Code

* **The target Infrastructure → Application → Domain structure is not implemented.** There are no source `domain` or `application` layers; HTTP controllers and mobile screens directly own authorization, SQL, transactions, caching, schema changes, and business rules.
* **Security-sensitive god objects create a systemic fail-open risk.** `posts.controller.ts` (2,741 lines), `user-hierarchy.service.ts` (1,675), `database.init.ts` (1,374), and mobile `databaseService.ts` (1,225) mix unrelated concerns and prevent isolated authorization/business-rule testing. Extract incrementally behind ports, starting with identity/permission rules, post updates, and allocation workflows.
* **SRS §2.5.7 privacy enforcement is absent.** The API contains no `anonymity_level` handling, so required Level 1–3 visibility, author redaction, follower checks, and operator-only access are not enforced server-side. Do not represent these privacy modes as available until schema, query projection, and authorization tests exist.
* **Duplicate post/feed behavior can drift across boundaries.** Mobile feed/items/rides maintain separate mapping/filter implementations, while rides and item services independently create linked post records. Characterize current payloads first, then consolidate shared domain/application rules without coupling them to UI or PostgreSQL.

## 🧹 Technical Debt & Maintenance

* **Dependency scanning regressed after Snyk removal:** neither root scripts nor `.github/workflows` run `npm audit`; the current 56 advisories have no merge gate. Add a maintained scanner with an explicit severity/exception policy rather than relying on ad hoc daily scans.
* **Security-critical behavior lacks regression coverage.** There are no focused negative tests for passwordless login, resolve-id proof, role mass-assignment, hierarchy actor binding, chat membership, rides/items ownership and races, session ownership, or rate-limit test-route exposure.
* **Generated and sensitive artifacts remain tracked.** Database backups, `tsc_output.txt`, `eslint-report.json`, ad hoc verification scripts, and build/security reports increase repository noise and leak risk. Classify, regenerate, ignore, or purge them; sanitize history where sensitive.
* **Open architectural debt should be addressed by blast radius, not file size alone.** Prioritize authentication/authorization boundaries and destructive DDL, then split shared transaction/use-case logic under characterization tests; defer cosmetic decomposition until those controls are stable.
