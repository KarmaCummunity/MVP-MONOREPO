# 🛡️ Daily Audit Report: 2026-07-12

## 🚨 Critical Vulnerabilities
* Committed environment dump exposes live infrastructure credentials (`DATABASE_URL`, `JWT_SECRET`, `REDIS_URL`, Google API/OAuth values) - File: `apps/api/railway_vars.txt:8` -> Action: Rotate all exposed credentials immediately, remove the file from the repository and git history, and add secret dump patterns such as `railway_vars.txt` / `*_vars.txt` to `.gitignore`.
* Startup environment validation contains database password fragments and host fingerprints in source - File: `apps/api/src/main.ts:151` -> Action: Replace secret-substring checks with non-secret environment markers such as `DB_ENV`, rotate affected database credentials, and scrub historical references.
* User profile update endpoint allows authenticated users to update arbitrary users and submit `roles` changes without binding the target to the JWT subject - Files: `apps/api/src/controllers/users.controller.ts:126`, `apps/api/src/services/user-profile.service.ts:349` -> Action: Require `req.user.userId === :id` for self-service updates and move `roles`, `firebase_uid`, and hierarchy fields behind `AdminAuthGuard`.
* Admin hierarchy actions trust request-body actor IDs instead of the authenticated principal - Files: `apps/api/src/controllers/users.controller.ts:64`, `apps/api/src/services/user-hierarchy.service.ts:492` -> Action: Derive the actor exclusively from `req.user`, reject body-supplied `requestingAdminId` / `requestingUserId`, and require admin guards for hierarchy mutations.
* Several high-impact write/read APIs are registered without guards, enabling unauthenticated mutation or PII access - Files: `apps/api/src/controllers/rides.controller.ts:37`, `apps/api/src/controllers/crm.controller.ts:38`, `apps/api/src/app.module.ts:103` -> Action: Add `JwtAuthGuard` / `AdminAuthGuard` as appropriate, bind all owner fields to the JWT subject, and redact PII on non-admin reads.
* Chat send endpoint permits unauthenticated sender impersonation when `sender_id` is supplied - File: `apps/api/src/controllers/chat.controller.ts:441` -> Action: Require `JwtAuthGuard` for message sends/read receipts and ignore or reject body user IDs that differ from the JWT subject.
* Rate-limit diagnostic controller is registered in the production controller list without an auth or environment gate - Files: `apps/api/src/app.module.ts:112`, `apps/api/src/controllers/rate-limit.controller.ts:155` -> Action: Remove this controller from production builds or protect every endpoint with `AdminAuthGuard` and an explicit non-production feature flag.
* Public Google Places proxy uses the server API key without authentication or per-user abuse controls - File: `apps/api/src/controllers/places.controller.ts:13` -> Action: Require auth and strict throttling, restrict Google key usage by origin/API, and rotate the key exposed in the committed environment dump.
* Web build persists access and refresh tokens in `AsyncStorage` / localStorage - File: `apps/mobile/auth/services/tokenManager.web.ts:7` -> Action: Move web refresh tokens to `httpOnly` secure cookies or another hardened web session strategy; avoid persistent localStorage for long-lived tokens.

## 🐞 Bugs & Logic Issues
* Profile ride tabs fetch all rides and filter client-side, downloading other users' ride records (including phone fields selected by the API) before local filtering - File: `apps/mobile/bottomBarScreens/profile/openRouteLoadOpenContent.ts:166` -> Recommendation: Add/use a server-filtered user rides endpoint and enforce API-side field redaction.
* `setManager` skips admin verification when `requestingUserId` is omitted - File: `apps/api/src/services/user-hierarchy.service.ts:492` -> Recommendation: Make the authenticated actor mandatory and fail closed when no admin principal is present.
* Sync user endpoint skips API-key validation when `SYNC_API_KEY` is unset and falls back to the default placeholder - File: `apps/api/src/controllers/sync.controller.ts:27` and `apps/api/src/controllers/sync.controller.ts:416` -> Recommendation: Fail startup when `SYNC_API_KEY` is missing outside tests and require `X-API-Key` consistently.
* SRS global rate limiting is configured but not applied as a global guard; only route-level guard usage is effective - File: `apps/api/src/app.module.ts:72` -> Recommendation: Register `ThrottlerGuard` as an `APP_GUARD` and keep route-specific overrides for higher/lower tiers.
* Admin view-only mode allows non-admin/guest navigation into admin surfaces that can trigger sensitive data reads - File: `apps/mobile/hooks/useAdminProtection.ts:60` -> Recommendation: Limit view-only routes to sanitized public data and enforce all sensitive reads on the server.

## 🏗️ Architecture & Clean Code
* Controllers continue to mix HTTP routing, SQL, cache invalidation, and business rules, especially rides, donations, stats, posts, and CRM. This conflicts with the target SSOT layering in `docs/SSOT/CODE_QUALITY/layers-and-boundaries.md` - Action: Extract business/application services incrementally and leave controllers as transport adapters.
* App module still registers diagnostic/test-style controllers in the main controller graph (`RateLimitController`, conditionally `RedisTestController`) - Action: Move diagnostic endpoints into a non-production-only module controlled by explicit configuration.
* Many high-risk controllers use plain TypeScript interfaces for request bodies, so the global `ValidationPipe` cannot enforce `class-validator` constraints or `forbidNonWhitelisted` on those inputs - Action: Introduce DTO classes on auth-sensitive write paths first.
* Authorization is inconsistently modeled: many endpoints accept `user_id`, `driver_id`, `donor_id`, `sender_id`, or actor IDs from client payloads rather than deriving identity from the JWT - Action: Add a shared actor-binding pattern and reject mismatched body/query identity fields.
* SRS-required operator matching, operator PII access controls, and audit logging remain absent from the current module map - Action: Track as a product gap and implement `/api/operator/*` with `OperatorAuthGuard` and immutable audit logs before exposing requester PII workflows.
